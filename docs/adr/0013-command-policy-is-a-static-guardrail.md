# Command Policy is a static guardrail, not a decision procedure for arbitrary shell

Command Policy statically refuses the well-known ways a command an Agent wants to run would reveal a bound Secret or read a Secret-bearing file directly, modeling real shell syntax as far as that stays precise, and fails closed — refuses, not silently runs unchecked — on a shell-invocation shape it cannot parse. What it is not, and has never tried to be, is a complete decision procedure for arbitrary shell. A command can compute what it does at run time in ways no amount of syntax modeling reaches: an interpreter's own `-c`/`-e` string is a program in a language this package does not parse; `eval` of a string built from another program's output is not resolvable from the text of the command alone; a program that opens a file itself, through an argument shape this package never modeled as file-like, gives no textual signal to catch; an unenumerated wrapper can rename or obscure the child process it execs. `docs/THREATS.md`'s own numbered list is the honest, standing account of exactly which such shapes this package does not attempt, added to as each is found rather than treated as a surprise.

This is a deliberate scope decision, not an oversight discovered late. A tool that tried to be a full decision procedure for shell would need to actually execute — or precisely simulate executing — the command to know what it does, which is a sandbox, not a static check that runs before a command is even allowed to start. ClaudePass already has the tool for that job: Redaction, which watches what a command's own stdout/stderr actually contain once it runs (`docs/adr/0002-redaction-in-the-broker.md`) and catches a value regardless of which of the shapes above produced it. Command Policy and Redaction are not doing the same job with different thoroughness; they are two different kinds of defense at two different points in a command's life, and the second exists precisely because the first cannot be made complete. `cpass import` closes the other half of this same class from the opposite direction: once a `.env`/`id_rsa`/etc. file's values are in the Vault, the plaintext file itself is shredded from disk (unless `--keep`), so there is decreasingly often a Secret-bearing file left for one of these unreachable shapes to open in the first place. Between what Command Policy statically refuses before a command runs, what Redaction strips from a command's own output as it runs, and what `cpass import` removes from disk once a Secret is Vaulted, the enforced boundary for a Secret's value is these three mechanisms together, not Command Policy alone.

This reframes how a newly found static bypass should be rated, which is the practical reason this ADR exists now: three rounds of audits against `internal/policy` (CLA-61/62 fixing command-splitting bypasses and a fail-open parser, CLA-63 through CLA-66 fixing hook false positives and glob exclusions, CLA-99 and CLA-100 each closing several further modeled-syntax gaps) kept finding new shapes, and each round's own writeup had to explain, freshly, why the previous round's "this is now complete" framing was wrong. It was wrong because completeness was never the right bar. The right question for a newly found shape is: does it regress something this package used to catch (a real bug, fixed as one), or is it a shape nobody modeled yet that a cheap, precise addition can close without the risk of a broader rewrite (the CLA-99/CLA-100 pattern, and this same audit round's own shell-behind-wrapper-heredoc, script-path-variable, and case-statement-pattern-arm fixes) — or is it a shape in the residual class this ADR names, disclosed here and in `docs/THREATS.md` rather than chased with an ever-more-elaborate parser that still would not reach it. A finding in the third category is not a broken guarantee; treating it as one is what pushes toward exactly the wrong fix — either refusing so broadly that real work breaks, or building a shell interpreter this package was never meant to be.

False positives are the other half of what this round's own audit weighed, and they are not a lesser concern than a bypass. `cpass policy --hook` runs on every single Bash tool call in every Agent session on a machine with cpass installed — not opt-in, not sampled, every one — so a refusal that shouldn't have fired blocks real work exactly as reliably as a bypass would have let something real slip through, just in the opposite direction. This round's own corpus of 349 real and hand-written commands found 8 newly-refused benign commands and 2 pre-existing ones from exactly this failure mode: precise modeling read as overly broad refusal (a bare `sh`/`bash` invocation receiving its script only via a wrapper's heredoc, a reader's own PATTERN argument mistaken for a filename it was never meant to be). Weighing a false positive as seriously as a bypass is what keeps the fix for each newly found gap narrow and precise rather than a blanket "refuse anything that looks unusual" — which would eventually refuse everything and teach every Agent session on the machine to route around the hook instead of trusting it.

## Consequences

- A future audit rates a newly found static bypass as: a regression (fix it, it is a real bug), a cheap precise addition (model the shape, the CLA-99/CLA-100/this-round pattern), or a residual-class finding (disclose it in `docs/THREATS.md` with a concrete example, per this ADR — not a reason to claim the guarantee was broken).
- A false positive in the PreToolUse hook is a first-class finding, reported and fixed with the same priority as a bypass, since the hook gates every Bash tool call unconditionally.
- `internal/policy`'s package doc comment, `docs/SECURITY.md`, `docs/PRD.md`, and the public security page state Command Policy's scope this way — the well-known static shapes it refuses, not an implied claim of completeness — and point here or at `docs/THREATS.md` rather than re-deriving the scope statement each time.
- `docs/THREATS.md` keeps the disclosed residual-class item (interpreters, `eval` of constructed strings, programs that open a file themselves, unenumerated wrappers) current with concrete examples as new instances are found, the same way its existing numbered list already tracks every narrower gap a specific audit round closed or left open.
- A change to what Redaction covers or what `cpass import` does to the source file is a change to one of this ADR's stated enforced boundaries and needs its own review against this document, not just against Command Policy's own rule set.
